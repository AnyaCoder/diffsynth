# 文生图模块下一阶段执行计划

> 制定日期：2026-09-11
> 目标：在现有专项生成基础上，提高目标尺度与位置稳定性，扩展雨、雪、雾和太阳阴影条件，并为国庆假期后的现场微调与部署验证做好准备。

## 1. 当前基线

- 已跑通 Qwen-Image-2512 文生图、LoRA 训练、LoRA 推理和 Web 任务管理链路；
- UI 已支持目标类型、型号、视角、朝向、构图、尺度、背景、天气、光线和阴影的结构化组合；
- 已形成固定 seed 的晴朗、细雨、薄雪、薄雾和浓雾样例；
- 2026-09-11 完成第二版提示词基线：目标尺度改用外接框比例描述，目标位置增加中心偏差和边界约束，天气条件增加可见线索及互斥排除项；
- 验证结果表明正俯视和目标位置可由提示词改善，但全机场远景中的降雨线索仍容易被模型忽略，提示词不能作为几何尺度和背景一致性的唯一控制手段。

## 3. 技术执行原则

### 3.1 目标尺度优化

1. 提示词继续保留外接框比例、中心偏差、边缘安全距离和完整性约束，作为无条件生成基线；
2. 验收尺度使用实际像素测量，不以提示词中的百分比直接作为完成证据；
3. DOM 场景按 `目标像素长度 = 目标实际长度 / GSD` 计算目标尺寸；
4. 正式稳定方案使用固定 DOM、目标 bbox/mask 和 Inpaint/ControlNet，避免扩散模型同时重画目标和背景；
5. 固定 seed 仅用于可复现，不作为背景一致性和尺度一致性的保证。

### 3.2 真实环境扩展

每种环境使用可检查的视觉线索，并与其他天气互斥：

| 条件 | 必须可见 | 必须排除 |
|---|---|---|
| 细雨 | 深色湿地、不规则积水、反光、雨滴波纹 | 积雪、白色雾幕、硬阴影 |
| 薄雪 | 连续薄雪、清扫带、车辙、积雪边缘 | 降雨、积水、大片裸露绿地 |
| 薄雾 | 半透明雾带、远处对比度下降、近处目标清晰 | 雨丝、积雪、大面积反光 |
| 浓雾 | 60% 至 80% 雾幕、背景大范围消隐、目标轮廓可辨 | 强阳光、降雪、明显积水 |
| 太阳阴影 | 方向、长度、软硬程度与光源一致 | 重复阴影、漂移阴影、矛盾光源 |

若全机场远景无法稳定表现雨滴等细粒度线索，验收重点改为湿地色调、积水与反光；雨丝和波纹只在满足对应 GSD 的近距场景中评价。

### 3.3 国产化适配

- 当前基座 Qwen-Image 属于国产模型，现有训练和推理实现仍依赖 PyTorch CUDA、NVIDIA 驱动及 GPU；
- 第一阶段部署目标为银河麒麟 V10-SP3、x86_64、NVIDIA GPU 和 Docker 24.x；
- 国产操作系统适配与国产 GPU 适配分开验收，不把麒麟系统部署等同于昇腾或其他国产 GPU 适配；
- 现场前收集操作系统、CPU 架构、GPU、驱动、容器运行时、离线软件源、磁盘、端口和权限信息；
- 现场验收至少覆盖离线模型加载、基础推理、LoRA 推理、小数据 LoRA 冒烟训练、UI、服务重启恢复和连续任务。

## 4. 现场微调输入清单

- 明确的首批型号、优先级和每个型号关键识别结构；
- 可合法使用的训练图、具体子型号标签、视角、天气、场景和目标 bbox/mask；
- 独立冻结测试集，避免与训练图近重复；
- 专家复核人员及“合格/不合格”的统一判定表；
- 目标服务器环境信息、可用 GPU 时段、离线传输方式和安全要求；
- 需要输出的 RGB、元数据、结构控制图和质量报告格式。

## 5. 进展汇报口径

每次进展只报告四项：本次完成内容、可复核证据路径、当前问题及原因、下一步和预计完成时间。生成结果必须同时保留 prompt、seed、steps、模型、服务和原图路径；不将提示词目标直接表述为已经达到的几何精度或型号准确率。

## 6. 算法接入决策

开源算法筛选和接入优先级见 `docs/open-source-algorithm-options-2026-09.md`。当前路线冻结为：先接 Qwen Blockwise ControlNet Inpaint，再做 Canny/Depth 消融；Grounding DINO + SAM 2 仅作为 bbox/mask 自动准备工具。GLIGEN、GeoDiffusion、DiffusionSat 和 T2I-Adapter 暂作论文/基线对照，不直接替换 Qwen-Image-2512。
